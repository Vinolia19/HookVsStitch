Behind the Crochet

The database design behind HookVsStitch — from tables and relationships to SQL concepts.

🧶

How HookVsStitch works

HookVsStitch uses a relational SQLite database to organize users, crochet projects, patterns, stitches, materials and progress.

Each table stores a specific type of information. Primary keys uniquely identify records, while foreign keys connect related tables.

9 Tables
5 Projects
5 Stitches
5 Indexes
🗃️

Database Tables

Each table has a specific responsibility in the HookVsStitch database.

👩‍🧶 users

Stores user account information.

PK user_id

🐰 projects

Stores crochet projects created by users.

PK project_id
FK user_id → users.user_id

🧵 patterns

Stores the crochet pattern associated with a project.

PK pattern_id
FK project_id → projects.project_id

📋 pattern_rows

Stores individual rows and instructions of a crochet pattern.

PK row_id
FK pattern_id → patterns.pattern_id

🪡 stitches

Stores the reusable stitch library.

PK stitch_id

🔗 row_stitches

Connects pattern rows with the stitches used in those rows.

PK row_stitch_id
FK row_id → pattern_rows.row_id
FK stitch_id → stitches.stitch_id

🧶 materials

Stores yarn, hooks, stuffing and other crochet materials.

PK material_id

🎀 pattern_materials

Connects patterns with the materials required for them.

PK pattern_material_id
FK pattern_id → patterns.pattern_id
FK material_id → materials.material_id

📈 progress

Tracks whether individual pattern rows have been completed.

PK progress_id
FK project_id → projects.project_id
FK row_id → pattern_rows.row_id
🔗

How the Tables Connect

Foreign keys create relationships between the tables.

👩‍🧶
Users → Projects

One user can have multiple projects. The projects.user_id foreign key connects each project to its owner.

🐰
Projects → Patterns

A project can have a pattern. The patterns.project_id foreign key connects the pattern to its project.

🧵
Patterns → Pattern Rows

A pattern contains multiple rows. Each row is connected using pattern_id.

🪡
Pattern Rows ↔ Stitches

The row_stitches table connects pattern rows with the stitches used in them.

🧶
Patterns ↔ Materials

The pattern_materials table connects patterns with the materials they require.

📈
Projects → Progress

The progress table records whether individual pattern rows have been completed for a project.

💻

SQL & DBMS Concepts Used

The main database concepts demonstrated in this project.

🔑

Primary Keys

Uniquely identify each record in a table. Examples include user_id, project_id and pattern_id.

🔗

Foreign Keys

Connect related tables and maintain relationships between records.

🔄

JOINs

Combine data from multiple related tables. For example, projects can be joined with users to display the project owner.

📊

GROUP BY

Groups records for calculations such as stitch usage and project statistics.

👁️

SQL VIEW

The project_progress_summary view provides reusable project progress calculations.

⚡

Indexes

Five indexes were created to improve lookup performance on commonly searched columns.

📌

Constraints

NOT NULL, UNIQUE, PRIMARY KEY and FOREIGN KEY constraints help maintain data integrity.

🧮

Aggregate Functions

COUNT, SUM and other calculations are used to generate project and stitch statistics.
